# 프로젝트 요구사항 정의서 (Requirements)

## 1. 실습 배경 및 목적
- 간단한 토이프로젝트를 직접 설계·구현하여 클라우드 플랫폼 **Railway**에 배포하는 전 과정을 실습한다.
- 단일 서버 배포를 넘어 **프론트엔드 + 백엔드 애플리케이션 서버 + 데이터베이스(RDBMS)** 로 구성된 풀스택 아키텍처를 설계하고 Railway 환경에서 연동·운영하는 방법을 익힌다.

---

## 2. 주제 및 핵심 기능 요구사항
- **프로젝트 주제**: 이메일 회원가입 및 로그인 기능이 있는 간단한 게시판 (Simple Board)

### 2.1 회원 인증 (Authentication)
- **이메일 회원가입**: 이메일(`email`, 최대 120자), 비밀번호(`password`, 8~64자), 닉네임(`nickname`, 2~50자)을 입력받아 회원을 등록한다.
  - 이메일 정규화(소문자화 및 공백 제거) 및 DB 유니크 제약(`uk_members_email`) 기반 동시 가입 충돌(`409 Conflict`) 방지
  - 비밀번호 해시 암호화(`BCrypt`) 저장 필수
- **이메일 로그인**: 가입한 이메일과 비밀번호로 인증 후 액세스 토큰을 발급받는다.
- **내 정보 확인 / 로그아웃**: 현재 로그인한 회원 정보를 조회할 수 있으며, 로그아웃은 클라이언트의 토큰 삭제(Stateless 구조)로 처리한다.

### 2.2 게시판 (Board CRUD)
- **게시글 목록 조회**: 비로그인 사용자를 포함한 모든 사용자가 작성된 게시글 목록(ID, 제목 최대 150자, 작성자 ID `authorId`, 작성자 닉네임 스냅샷, 작성일시)을 페이징(`page`, `size`) 기반으로 최신순 조회할 수 있다 (목록 조회 시 본문 제외로 대역폭 최적화).
- **게시글 상세 조회**: 특정 게시글의 본문 내용과 작성자 정보를 조회할 수 있다.
- **게시글 작성**: 로그인한 회원만 새 게시글(제목 1~150자, 본문 1자 이상)을 작성할 수 있으며, 작성 시점의 닉네임을 스냅샷으로 보관한다.
- **게시글 삭제**: 게시글을 작성한 본인(`authorId` 일치)만 자신의 게시글을 삭제할 수 있다.

## 3. 기술 스택 요구사항

| 영역 | 선택 기술 스택 | 선정 이유 및 실습 포인트 |
| :--- | :--- | :--- |
| **Frontend** | **React (Vite) + FSD 아키텍처** | Feature-Sliced Design(`app`, `pages`, `widgets`, `features`, `entities`, `shared`) 계층 분리 및 SPA API 통신(`VITE_API_URL`) 실습 |
| **Backend** | **Spring Boot 3 (Java 21) + JPA + 모듈러 모놀리스** | 도메인 모듈(`member`, `post`, `shared`) 단위 패키지 격리, 로컬(`local`)/운영(`prod`) 프로필 분리, 동적 `PORT` 바인딩, 운영 시크릿 검증 실습 |
| **Database** | **PostgreSQL** (로컬 테스트 시 H2 지원) | Railway PostgreSQL 플러그인 프로비저닝 및 변수 참조 문법(`${{Postgres.PG*}}`) 연동 실습 |
| **Deployment** | **Railway (대시보드 기반 멀티 서비스 배포)** | 단일 GitHub 저장소에서 Frontend / Backend / PostgreSQL 3개 서비스를 각각 구성·연결하는 실습 (deprecated된 railway.json 대신 대시보드 공식 설정 가이드 적용) |

## 4. 실습 진행 방식 요구사항
- **실습 가이드 + 보일러플레이트 코드 함께 구성**:
  - 핵심 배포 설정(`Dockerfile`, Nginx 템플릿, `application.yml`), 백엔드 API, DB 연동 및 React 프론트엔드 코드를 논리 단위로 세팅한다.
  - 사용자가 Railway 대시보드에서 직접 DB와 서버를 띄우고 환경변수를 연결해 볼 수 있도록 단계별 실습 가이드를 함께 제공한다.
- **개발 워크플로우 (`staged-commit-workflow`) 준수**:
  - 작업을 응집된 논리 단위(커밋당 300~400줄 이내)로 분할하여 로컬 커밋한다.
  - 원격 저장소 `git push`는 사용자가 직접 수행한다.
